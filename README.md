## 快速开始

### v2（主推版本）

```bash
cd v2
cp .env.example .env      # Windows 下注意别变成 .env.txt，填入模型 key
node server.js            # 打开 http://127.0.0.1:8130
```

不填 key 也能跑：界面显示「离线讲解 · 预置史料」，回答来自服务端史料检索
与人工撰写的离线问答库，超纲问题照样拒答。

**断网保命**：直接双击 `v2/index.html` 也能完整演示
（`data/corpus.fallback.js` 是同源兜底副本）。

### 变成网址给别人看

```bash
python tools/build_deploy.py     # 生成 dist/ 和 dist.zip（3.2MB）
```

把 `dist.zip` 拖到 [腾讯云 EdgeOne Pages](https://console.cloud.tencent.com/edgeone/pages)
即可上线，免备案、国内节点。详细步骤见 [部署上线说明.md](部署上线说明.md)。

纯静态托管也能完整使用：AI 走本地检索兜底，回答照样带史料出处、超纲照样拒答。

### v1（兜底版本）

```bash
node server.js            # 打开 http://127.0.0.1:8123
```

## 两个关键工程决策

### 一、检索逻辑只有一份

v1 的检索算法在 `app.js` 和 `api/chat.js` 各写了一遍，阈值还不一样
（前端 0.15 / 后端 0.42），导致同一个问题「离线能答、在线拒答」。

v2 把它抽到 `v2/js/domain/retrieval.js`（UMD 打包），前端 `<script>` 引入、
后端 `require` 同一份文件。**一份实现、一个阈值、一套语料。**

### 二、代码与计划书对齐

- 教师端用学校生成的**匿名编号**，不出现真实姓名（对齐计划书 6.3）
- 研学评语由**模板拼接**，引用学生自述原文，不由模型自由生成
  （对齐计划书 2.6「AI 不给未成年人写评价」）
- AR 模块如实标注**方案设计阶段、尚未进入原型**，不做假的演示
