# 把这个 Demo 变成网址

> 目标：别人点一个链接就能打开、能用，不用装任何东西。
> 前提：`dist.zip` 已经打好（`python tools/build_deploy.py` 生成，3.2MB）。

---

## 先说结论：选哪个

| 方案 | 国内访问 | 能跑 AI 真模型 | 难度 | 推荐场景 |
|---|---|---|---|---|
| **腾讯云 EdgeOne Pages** | 快（国内节点） | 需改造 | ★☆☆ 拖拽上传 | **给别人看、路演扫码** |
| Vercel | 一般（常被墙） | 能，直接跑 `api/chat.js` | ★★☆ 连 GitHub | 评委/老师能翻墙 |
| GitHub Pages | 慢/不稳 | 不能 | ★★☆ 配分支 | 和代码放一起存档 |

**建议：先用 EdgeOne Pages 上线（纯静态版，功能完整），需要真模型时再考虑 Vercel。**

为什么纯静态就够：这个项目从设计上就支持「没有后端也能完整演示」——
AI 回答走 `js/core/net.js` 的本地兜底，用同一份检索算法 + 人工撰写的离线问答库。
**回答照样带史料出处，超纲问题照样拒答。** 已经实测验证过。

## 方案一：EdgeOne Pages（推荐，5 分钟）

### 步骤

1. **开通**
   打开 https://console.cloud.tencent.com/edgeone/pages
   用微信/QQ 登录（腾讯云账号），点「立即开通」。免费，不扣费。

2. **上传**
   点「新建项目」→ 选「直接上传」（有的版本叫「本地上传」）
   把 **`dist.zip`** 拖进去
   项目名填英文小写，比如 `dazhan-hongtu` —— 会出现在网址里

3. **部署**
   点「开始部署」，等 20–40 秒

4. **拿到网址**
   形如 `https://dazhan-hongtu.edgeone.app`
   打开就是你的网站，自动 HTTPS。

### 注意

- **不需要备案**。默认的 `*.edgeone.app` 子域名可以直接用。
  只有绑自己的域名（如 `hongtu.com`）且要国内加速时，才需要 ICP 备案（免费但审核 1–2 周）。
- 单个文件上限 25MB。`dist` 里最大的图片 1.8MB，没问题。
- 更新内容：控制台里找到项目 → 「更新部署」→ 重新拖 zip。

## 方案二：Vercel（能跑真模型）

这个方案的好处是 `api/chat.js` 会跑起来，AI 走真实模型而不是离线库。

### 步骤

1. 打开 https://vercel.com ，用 **GitHub 账号**登录（你的 `coder-jie-zhao`）
2. 点 **Add New → Project** → 选 `dazhan-hongtu` 仓库 → **Import**
3. 关键：**Root Directory** 填 `dist`
   （不是 `v2`——`dist` 才是剔掉素材的干净包，`api/chat.js` 的 `require("../data/corpus.json")` 在 `dist` 结构下正好对）
4. **Environment Variables** 加三个（从你 `.env.example` 抄）：
   ```
   LLM_API_KEY      你的密钥
   LLM_BASE_URL     https://api.deepseek.com/v1
   LLM_MODEL        deepseek-chat
   ```
5. 点 **Deploy**

部署完拿到 `https://dazhan-hongtu-xxx.vercel.app`。

### 不填 key 会怎样

`api/chat.js` 会自动降级成「服务端史料直出」——有出处、能拒答，但措辞是史料原文而非模型组织。
比纯静态版好一点（检索在服务端跑），但不如有 key。

## 方案三：GitHub Pages（存档用）

适合「代码和演示放一起」。但注意 Pages 只能指向仓库根或 `docs/`。

```bash
# 在仓库里
mkdir -p docs
# 把 dist 的内容拷进 docs/
cp -r dist/* docs/
git add docs && git commit -m "deploy: 生成 Pages 站点"
git push
```

然后仓库 **Settings → Pages** → Source 选 `Deploy from a branch` → Branch 选 `main` / 目录选 `/docs`。

网址：`https://coder-jie-zhao.github.io/dazhan-hongtu/`

（`index.html` 全部用相对路径，放在子目录 `/dazhan-hongtu/` 下能正常工作，已确认。）

## 上线后建议做三件事

### 1. 生成二维码（路演必备）

你之前那个 `_不用了-二维码/` 目录里写过「扫码打不开」，原因是**当时没有真实网址**，
二维码指向的是 `file:///D:/...` 本地路径，别人手机当然打不开。

现在有了 `https://xxx.edgeone.app`，二维码就能用了：

- 打开 https://cli.im （草料二维码），粘贴网址，生成，下载 PNG
- 打印在 PPT 尾页 / 展板上，评委手机一扫就打开

### 2. 第一次打开时自己走一遍

用手机流量（不要连 WiFi）打开网址，确认：
- 首页能出来，三张点位图能加载
- 点「问 AI」能答、能拒答
- 任务能做、报告能生成

**一定要用手机流量测**——校园网/公司网可能有特殊限制，测出来的结果不代表评委现场的情况。

### 3. 演示时带两条路

路演现场的网络不可信。所以：

- **主路**：手机/笔记本打开网址，走正常流程
- **备路**：笔记本双击 `v2/index.html`（file:// 直接跑，已实测可用）

链接挂了就切备路，别在台上折腾网络。

## 更新内容后怎么重新部署

改完代码后：

```bash
python tools/build_deploy.py
```

会重新生成 `dist/` 和 `dist.zip`（自动剔掉 `PPT素材/`、`_shots/`，只留 3.2MB）。
然后把新的 `dist.zip` 拖到平台上覆盖即可。

## 附：为什么部署包里没有 PPT 素材和截图

`v2/` 有 18.4MB，其中：

- `PPT素材/` 9.8MB —— 做 PPT 用的成品图
- `_shots/` 5.2MB —— 开发时的界面截图

这些是给你自己做材料的，别人打开网站不需要。而且这两个目录里有 28 个中文文件名，
部分托管平台处理中文 URL 会出编码问题。剔掉后：

- 体积 18.4MB → **3.2MB**（省 83%）
- 中文文件名 28 个 → **0 个**
- 首屏加载明显更快，手机流量也扛得住
