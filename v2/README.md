# 大展红途 v2 · 井冈山红色研学智能导览

> v2 是 v1（黄洋界单点位原型）的全量重构。v1 保留在仓库根目录作为路演兜底，
> v2 在 `v2/` 目录，两版可独立运行、互不影响。
>
> 版本：v2.0.0 ｜ 2026-10-27

## 一、v2 相对 v1 改了什么

### 1. 架构：从「一个 742 行的文件」到分层

v1 的 `app.js` 一个文件里塞了数据、检索、渲染、评分、事件绑定，742 行。
v2 按职责拆开，每一层只有一件事：

```
v2/
├── index.html              页面骨架（9 个视图容器）
├── styles/
│   ├── tokens.css          设计令牌：颜色/字阶/间距/圆角/阴影/动效
│   ├── base.css            基础层与通用组件
│   └── views.css           各视图样式
├── js/
│   ├── core/               核心层（不关心业务）
│   │   ├── store.js        单一状态源 + 发布订阅 + 持久化
│   │   ├── router.js       hash 路由 + 视图转场 + 生命周期
│   │   ├── motion.js       动效引擎（涟漪/打字机/计数/滑动手势/拖拽）
│   │   └── net.js          网络层（超时/降级/三级兜底）
│   ├── domain/             领域层（前后端共用，UMD 打包）
│   │   ├── retrieval.js    史料锚定检索  ← 唯一一份实现
│   │   ├── scoring.js      评分引擎 + 评语模板
│   │   ├── taskgen.js      按学段生成任务单
│   │   ├── prompt.js       角色化 system prompt
│   │   └── cases.js        34 项验收用例集
│   ├── views/              视图层（9 个，各自管自己的渲染与交互）
│   │   ├── home.js  point.js  chat.js  task.js  report.js
│   │   └── teacher.js  audit.js  selftest.js  ar.js
│   └── app.js              应用入口（装配）
├── api/
│   └── chat.js             Serverless Function（检索 + 生成）
├── data/
│   ├── corpus.json         37 条已审核史料 + 3 个点位 + 任务 + 评分规则
│   └── corpus.fallback.js  file:// 兜底副本（自动生成，勿手改）
├── server.js               本地服务（静态托管 + API + 自测接口）
└── assets/img/             11 张官方实景照片 + credits.json
```

**最关键的一处修正**：v1 的检索算法在 `app.js` 和 `api/chat.js` 各写了一遍，
阈值还不一样（前端 0.15 / 后端 0.42）。结果是同一个问题「离线能答、在线拒答」——
评委只要问一句「为什么这个题你在台上能答、后台就拒答了」，整个技术护城河的说法就塌了。

v2 把检索抽到 `js/domain/retrieval.js`，用 UMD 打包，前端 `<script>` 引入、
后端 `require` 同一份文件。**只有一份实现、一个阈值、一套语料。**

### 2. 功能：从 1 个点位到 3 个点位，6 个视图到 9 个

| | v1 | v2 |
|---|---|---|
| 点位 | 黄洋界 | 黄洋界 · 八角楼 · 龙江书院 |
| 语料 | 18 条 | 37 条，全部带官方出处链接 |
| 任务 | 3 题（看/想/理） | 4 题（看/想/理/**说**），按学段动态生成 |
| 视图 | 6 | 9（新增审核管线 / 检索自测 / AR 规划） |
| 教师端 | 纯展示 + 真实姓名 | 匿名编号 + 任务单生成器 |
| 实景照片 | 0（纯 SVG） | 11 张井冈山革命博物馆官网实景 |

**补上的三块，都是计划书写了但 Demo 里没有的**：

- **任务四「说」**（计划书 2.1 动线里的 9:15「写下自述」）——v1 报告里的
  「我的思考」其实用的是任务二的理由，自述这一环不存在。
- **任务单生成器**（计划书 1.4 模块二）——v1 的教师端只能看，改不了。
  v2 能选学段 + 点位，实时生成任务单，并说明每道题为什么适合这个学段。
- **内容审核管线 + 语料溯源**（计划书第五章，全篇最大的创新点）——v1 完全看不见。
  看不见 = 不存在。v2 把四环节摊开，37 条语料逐条可点开核查出处。

**删掉的一处**：`api/comment.js`。v1 真的调 LLM 生成研学评语，
但计划书 2.6 写得很清楚：「评语由模板与学生自述拼接，不由模型自由生成……
AI 给未成年人写评价，在合规上是不该碰的红线」。v2 改为模板拼接，
评语里引用的判断句全部来自学生自己写的理由与自述。**代码与计划书对齐了。**

### 3. 合规：教师端不再有真实姓名

计划书 6.3：「系统不采集学生姓名、照片等个人敏感信息。研学报告使用学校生成的
匿名编号关联，编号与真实身份的映射表由学校自行保管，系统侧不建立、不存储该映射关系。」

v1 的 `app.js` 里硬编码了「赵杰、李雯、王浩、陈曦、刘洋」五个真实姓名——
和计划书直接冲突。v2 全部换成 `JX-2401` 形式的匿名编号，并在界面上标注这一点。

### 4. 交互：从 2 套 CSS 动画到一套动效引擎

v1 全站只有 `fade` / `rise` 两套动画，没有转场、没有手势、没有骨架屏、没有微反馈。
v2 的 `core/motion.js` 提供：

| 能力 | 用途 |
|---|---|
| 视图转场 | 前进 push / 后退 pop，方向感知 |
| 涟漪 | 按钮、选项、卡片按压反馈 |
| 打字机 | AI 回答逐字出现（长按可跳过） |
| 数字滚动 | 统计数字、能力分条 |
| 横滑 carousel | 点位信息卡（三张卡滑动，带指示点） |
| 拖拽排序 | 任务三的排序题（pointer 事件，手机可用） |
| 骨架屏 | 检索中显示「正在查阅史料…」 |
| 抖动反馈 | 答错时卡片 shake |
| 轻震动 | 关键操作 `navigator.vibrate` |

另外：长按输入框可触发**三角色并排对照**（同一个问题，三种视角同时回答），
这是 v2 新增的关键交互，把「三种身份」从切换器变成了可对比的产品特征。

全部尊重 `prefers-reduced-motion`。

## 二、运行方式

### 方式 A：本地服务（推荐，能走真模型）

```bash
cd v2
cp .env.example .env        # Windows 下注意别变成 .env.txt
# 编辑 .env 填入 key
node server.js
```

浏览器打开 `http://127.0.0.1:8130`

`.env` 内容：

```ini
LLM_API_KEY=你的密钥
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
```

`LLM_BASE_URL` 与 `LLM_MODEL` 必须配套。也可用智谱 GLM（`glm-4-flash` 免费档）、
阿里通义（`qwen-plus`）等 OpenAI 兼容接口。

**不填 key 也能启动**，此时：

- 界面右上角显示黄色 ●「离线讲解 · 预置史料」
- 回答来自服务端史料检索 + 人工撰写的离线 QA 库（**不是 503 白屏**）
- 超纲问题照样拒答

### 方式 B：双击 index.html（断网保命）

直接双击 `v2/index.html` 即可。此时 `fetch("data/corpus.json")` 被 CORS 拦，
由 `data/corpus.fallback.js`（自动生成的同源副本）兜底，功能不中断。

> ⚠️ 双击模式下无法调用后端，AI 回答走纯前端离线路径。

### 方式 C：部署到 Vercel

`api/chat.js` 是标准 Serverless Function 格式，直接上传 `v2/` 目录即可。
环境变量配 `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL`。

## 三、验证与答辩素材

### 检索验收自测

界面内：**首页 → 检索自测**（或直接访问 `#/selftest`），点「一键重跑」。

34 项用例：20 项应答类（语料覆盖范围内的问题必须命中正确条目）＋ 14 项拒答类
（超纲、涉评价、景区服务类必须拒答）。

跑的是**生产代码里的同一份检索实现**（`js/domain/retrieval.js`），
与线上行为完全一致——不会出现「页面上 34/34，命令行却是 32/34」。

命令行版本：

```bash
node _test.js              # 34 项用例
curl http://127.0.0.1:8130/api/selftest    # JSON 格式
```

> 当前状态：**34 / 34 全部通过**。

### 修检索时踩过的坑（可直接讲给评委听）

最早检索层用纯关键词匹配，「朱德为什么挑粮」因为共享「朱德」二字，
错误命中了「纪念碑」条目——这类错误在演示中很难被肉眼发现，只有用例能抓住。
修法是引入 IDF 加权（罕见词权重高、泛用词权重低）并补上领域词表。

另外还修掉一个隐藏 bug：停用词表里的「什么」「怎么」「为什么」是双字词，
但实现用的是 `Set.has(单字)` 逐字匹配——**这些双字词从未生效**，
一直在污染 bigram 匹配。修成「多字词整串剔除 + 单字词逐字剔除」后，
「毛泽东在这里写了什么诗」这类口语问法才正确命中。

### 三个最值得讲的演示动作

1. **拒答**：问「黄洋界的门票多少钱」→ 固定话术拒答 + 引导提问
2. **三角色对照**：长按输入框 → 同一个问题三种视角并排
3. **自测台**：当场重跑 34 项，全绿

## 五、图片版权与出处

`v2/assets/img/` 下 11 张照片全部来自**井冈山革命博物馆官网**
（`jgsgmbwg.com`），每张的原始 URL 与对应文章页都记录在 `credits.json`。

这是刻意选的：官网图版权最稳、答辩时来源最好讲，且与「内容可追溯」的产品主张一致。

## 六、v1 与 v2 的关系

- `v1/`（仓库根目录的 `index.html` / `app.js` / `styles.css` / `api/` / `data/`）
  是上一版原型，**原样保留**，作为路演现场的兜底方案。
- v2 在 `v2/` 目录，两版端口不同（v1: 8123，v2: 8130），互不干扰。
- 如果 v2 在现场出问题，立刻切回 v1。

版本历史见 Git tag：`v1.0.0`（黄洋界单点位基线）、`v2.0.0`（本次重构）。
